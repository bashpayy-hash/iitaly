# Восстановление ИИ-проверки

12 октября 2026 production `web` получил от Anthropic HTTP 401 `authentication_error`, `invalid x-api-key`. Переменная `ANTHROPIC_API_KEY` существовала; одно её наличие не подтверждает доступ. Текущий сбой требует действующего API-ключа. Из ответа нельзя установить, был ли старый ключ отозван, истёк или был скопирован неверно.

## Проверки и поведение

- Ключ очищается от внешних пробелов и случайных парных кавычек; внутренние пробелы считаются ошибкой конфигурации. Значение не пишется в лог и не отдаётся клиенту.
- При старте и по запросу доступ проверяется через `GET /v1/models/{model_id}`. Документы и платные запросы генерации в этой проверке не используются. Ответ кэшируется на 60 секунд, параллельные проверки объединяются.
- `/health` остаётся проверкой жизнеспособности сервера и хранилища, дополнительно показывает последний статус `ai`. Ошибка ИИ не перезапускает оплату и кабинет.
- `/health/ai` возвращает 200 `AI_READY` или 503 с безопасным кодом причины. Нельзя использовать только зелёный `/health` как подтверждение работы проверки документов.
- 401/403/404 в реальном запросе немедленно сбрасывают положительный статус. Следующие документы и сообщения не отправляются провайдеру до успешной повторной проверки метаданных. Старый параллельный probe не может затереть отказ.
- Модельная метаинформация проверяет ключ и доступ к модели; она не доказывает наличие баланса, свободной квоты или способность прочитать конкретный PDF. После замены ключа нужен отдельный синтетический документ.

## Замена ключа

1. В Claude Console создать рабочий API-ключ нужного workspace, проверить его статус и срок действия. Для сервера использовать отдельный управляемый ключ с подходящей политикой ротации.
2. В Railway: проект `thorough-intuition` → environment `production` → сервис `web` → Variables → заменить **только** `ANTHROPIC_API_KEY`. Секрет вводится в Railway, не в GitHub, исходный код или чат. `DATA_KEY` не менять: он шифрует существующие данные клиентов.
3. Применить изменение и дождаться `SUCCESS` нового deployment. Новый процесс перечитает переменную.
4. Выполнить `BASE=https://web-production-9faf3.up.railway.app node scripts/check-ai-health.js`. Код выхода должен быть 0, статус — `AI_READY`.
5. На сайте проверить один искусственный TXT/PDF без персональных данных, затем посмотреть, что `/api/check-document` вернул 200 и содержательный `result`. Один только deploy `SUCCESS` не подтверждает доступ к Anthropic.

При `AI_AUTH_INVALID` нужна проверка ключа; `AI_PERMISSION_DENIED` — прав workspace; `AI_MODEL_UNAVAILABLE` — `ANTHROPIC_MODEL`; `AI_PROVIDER_UNAVAILABLE` — сети или состояния провайдера. Источники: [ошибки Claude API](https://platform.claude.com/docs/en/api/errors), [аутентификация](https://platform.claude.com/docs/en/manage-claude/authentication), [метаданные модели](https://platform.claude.com/docs/en/api/models/retrieve).

## Регрессии

`node --test test/*.test.js` проверяет нормализацию, отсутствие передачи секрета в статусах, кэш, параллельные запросы, восстановление, отказ после успешного probe и защиту от устаревшего ответа. Серверные сценарии отдельно подтверждают блокирование чата/документов при 401, работоспособность `/health` и прежний формат успешного результата. CI использует синтетические ответы; его успех не подменяет проверку production.
